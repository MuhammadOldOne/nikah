# Перенос данных старого бота

`scripts/import_legacy.py --import` переносит базу текущего бота @nikah_istina_bot (SQLite `data.db`)
в базу новой системы по правилам [LEGACY_BOT.md, §4](LEGACY_BOT.md). Номера анкет, id откликов,
чатов и сообщений сохраняются, поэтому старые кнопки в Telegram указывают на те же записи.

Перенос запускается **на сервере** в контейнере `web`, по шагам [CUTOVER.md](CUTOVER.md). Здесь —
что именно он делает, как читать отчёт и какие решения приняты для особых случаев.

## Безопасность

- **Источник только читается.** Файл открывается в режиме SQLite `mode=ro` с `PRAGMA query_only`, а в
  контейнер подключается с `:ro`. Переносится **копия**, снятая через `sqlite3 … ".backup …"`; сам
  `data.db` старого бота не трогается и остаётся для отката.
- **Одна транзакция.** Без `--commit` — пробный прогон: всё проверяется, затем откатывается. С
  `--commit` — запись. Ошибка на любом шаге отменяет всё.
- **Только в пустую базу.** Если в новой базе уже есть анкеты, отклики, чаты или сообщения, перенос
  отказывается работать. Пользователи без анкет (например, админы из `make_admin.py`) допустимы: их
  объединяют с перенесёнными по Telegram ID.
- **Один раз.** Признак выполненного переноса хранится в базе (`app_meta.legacy_import`), второй запуск
  с `--commit` отказывает. Тот же признак показывает сводка админки.
- **Сверка.** После записи количество строк в каждой таблице сверяется с перенесённым; при расхождении
  всё откатывается.
- **Без данных в выводе.** Отчёт содержит только количества и предупреждения — без имён, текстов,
  username и id; его можно пересылать. Ошибка базы данных печатается только типом и именем ограничения.
- **Без уведомлений.** Перенос не создаёт событий: людям ничего не приходит.
- На время переноса (секунды) таблицы людей заблокированы для записи: сайт и бот подождут.

## Команда

```bash
cd /opt/nikah
# пробный прогон (ничего не записывает)
docker compose run --rm -v /opt/legacy/data.db:/legacy/data.db:ro web \
  python -m scripts.import_legacy --import /legacy/data.db
# запись
docker compose run --rm -v /opt/legacy/data.db:/legacy/data.db:ro web \
  python -m scripts.import_legacy --import /legacy/data.db --commit
```

Файл должен быть читаем пользователем контейнера (UID 10001): `chown 10001:10001 /opt/legacy/data.db`.
Код выхода: `0` — успешно, `1` — отказ или ошибка (причина в stderr), `2` — неверные аргументы.

## Что и как переносится

| Старая таблица → новая | Правила |
|---|---|
| `users` → `users` | `telegram_id = user_id`, `username = tg_username` (без `@`), `is_banned = banned`, `created_at`. `is_admin` — `role = 'admin'` или id из `ADMIN_TELEGRAM_IDS` (этот флаг остаётся и после правки `.env`: снимать права — `make_admin --revoke`, DEPLOY.md §12). `consent_at` пусто: согласие (152-ФЗ) бот и сайт спросят при первом заходе. |
| `profiles` → `profiles` | `number = id`; пол `m`/`f` → брат/сестра; `birth_year = год(created_at) − age`; город, национальность, «о себе», `wishes = partner_wishes` — как есть. Статус: `approved` → опубликована, `pending` → на модерации, `rejected` → отклонена, `paused` → скрыта. `submitted_at = created_at`, `approved_at = updated_at` у одобренных. Семейное положение, дети, образование, занятость — пустые: анкета неполная, владельцу предложат дополнить. |
| `interests` → `interests` | id сохраняется, анкеты заменяются их владельцами, статус как есть, без сообщения. |
| `chats` → `conversations` | id сохраняется, пара упорядочивается. Открыт — `opened_at`; закрытый чат — `closed_at` с причиной «завершён участником». Ссылка на принятый отклик пары, если он есть; время последнего сообщения. |
| `messages` → `messages` | id сохраняется; отправитель — владелец анкеты; текст как есть; канал — Telegram; всё старое считается прочитанным. Пометка `flagged` сохраняется, а `witness_note` переводится в код (ниже). |
| `muted` | не переносится (в старом боте не использовалась); строки, если есть, считаются в предупреждении. |
| `sqlite_sequence` | номер новой анкеты продолжает `max(id, sqlite_sequence)`: номера удалённых анкет тоже не выдаются повторно. То же для id откликов, чатов и сообщений. |

Время в старой базе записано SQLite в UTC без зоны и читается как UTC.
Не переносятся: id сообщений Telegram старой пересылки (`tg_message_id_*`) и незаконченные действия,
которые старый бот держал в памяти (регистрация, «Написать в чат» свидетеля).

## Решения для особых случаев

Старый бот не проверял связи между таблицами (в SQLite они не включены), а кое-что допускал из-за
гонок. Перенос обрабатывает каждое такое состояние так:

| Случай | Что делает перенос |
|---|---|
| Отклики в обе стороны, оба ожидают ответа | переносятся оба (новая база это допускает) |
| Принятый отклик, чат по нему уже закрыт | как есть; повторный отклик в ту же сторону невозможен, в обратную — возможен |
| Несколько чатов одной пары (закрыли, потом открыли снова) | все переносятся; каждому чату по порядку времени сопоставляется принятый отклик пары (сам старый бот этой связи не хранил) |
| Два **открытых** чата одной пары (гонка при принятии) | открытым остаётся новый, старый закрывается временем открытия нового |
| У человека открыты чаты с разными людьми | переносятся как есть; бот предложит выбрать, в какой чат отвечать |
| Чат без принятого отклика | переносится без ссылки на отклик |
| Анкета, у владельца которой нет строки в `users`; отклик или чат со ссылкой на отсутствующую анкету; сообщение в отсутствующем чате или от анкеты не из этого чата | пропускается и считается в предупреждении |
| Возраст, из которого получается год рождения вне 18–80 (бот так не мог, только ручная правка) | год рождения ограничивается диапазоном, анкета помечается «возраст при переносе» и, если была опубликована, уходит на модерацию: возможно несовершеннолетнюю анкету никто не увидит без проверки |
| Тексты длиннее или короче нынешних ограничений | переносятся как есть; при правке анкеты проверяются только изменённые поля. Обрезается только то, что не помещается в колонку базы (город > 60, национальность > 50, username > 64 символов) |
| Пустая национальность или «о себе» | переносятся как «не указано» |
| `witness_note` | `contact-leak filter` → «фильтр контактов», `user_report` → «жалоба», `flagged by <id>` → «свидетель» (Telegram ID свидетеля не копируется), любая другая заметка → «свидетель» |
| Заблокированный с ожидающими откликами или открытым чатом | переносится как есть (в старом боте так и было), в отчёте — количество |
| Админ, заблокированный в старой базе | блокировка не переносится: в новой системе админа нельзя заблокировать (сначала снимают права) |
| Человек уже есть в новой базе (например, админ из `make_admin.py`) | объединяется по Telegram ID: права админа и согласие сохраняются, пустой username дополняется, дата регистрации — более ранняя |

## Отчёт

```
Перенос данных старого бота (файл SQLite открыт только для чтения).

Таблица                   в старой базе   перенесено   пропущено
users → users                        81           81           0
profiles → profiles                  46           46           0
...
Пользователи, которые уже были в новой базе (объединены по Telegram ID): 0
Сверка: количество строк в новой базе совпадает с перенесённым.

Предупреждений нет.

ПРОБНЫЙ ПРОГОН: все изменения отменены, новая база не изменилась.
```

### Предупреждения

| Текст (начало) | Что значит и что делать |
|---|---|
| анкеты, владельца которых нет в users | строки `profiles` без `users`; такие анкеты и всё, что на них ссылается, пропущены. Обычно их нет — если есть, пришлите отчёт разработчику до `--commit` |
| анкеты с неизвестным полом / статусом | ручная правка старой базы; без пола анкета пропущена, с неизвестным статусом — уходит на модерацию |
| анкеты с возрастом вне 18–80 | см. «Решения»: после переноса проверьте их в админке («Помеченное» → «Анкеты») |
| значения длиннее поля новой базы — обрезаны | город, национальность или username не поместились в колонку |
| анкеты с текстами вне нынешних ограничений длины | только информация: тексты перенесены как есть |
| отклики / чаты со ссылкой на отсутствующую анкету, отклики анкеты самой себе, отклики с неизвестным статусом | пропущены: им не на кого указывать |
| лишние открытые чаты одной пары | см. «Решения» |
| чаты без принятого отклика | только информация |
| люди с несколькими открытыми чатами | только информация; бот спросит, в какой чат отвечать |
| заблокированные с ожидающими откликами или открытыми чатами | собеседник может сам завершить общение; чтобы закрыть всё сразу, в админке разблокируйте и снова заблокируйте человека — блокировка закрывает его чаты и отменяет отклики |
| администраторы с блокировкой в старой базе | проверьте в админке, должны ли они оставаться админами |
| сообщения в отсутствующих чатах / от анкеты не из этого чата | пропущены |
| сообщения длиннее 2000 символов | только информация: перенесены как есть |
| неизвестные отметки свидетеля | перенесены как отметка свидетеля |
| строки в muted | таблица не переносится |

## Просмотр схемы (`--inspect`)

`--inspect` печатает только таблицы, колонки, типы, связи и количество строк любой базы SQLite
(или PostgreSQL по `postgresql://…`) и никогда — содержимое строк. Нужен только стандартный Python,
поэтому файл скрипта можно запустить и вне проекта:

```bash
python3 scripts/import_legacy.py --inspect /opt/legacy/data.db
```

## Конфиденциальность

Анкеты никах-сервиса раскрывают религиозные убеждения (особая категория данных, 152-ФЗ), а ещё
Telegram ID, города, семейное положение и переписку. Поэтому в репозиторий (он публичный), issues,
чаты и письма **нельзя** отправлять `data.db`, его копии, дампы, выгрузки, скриншоты анкет и
переписки, логи с данными, `.env` и токены. Пересылать можно только отчёт переноса и вывод `--inspect`.

Копии `/opt/legacy/*.db` удалите, когда откат точно не понадобится ([CUTOVER.md](CUTOVER.md), шаг 7).
