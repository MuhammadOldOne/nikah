# Никах-платформа «Истина»: структура сайта и MVP

Сайт и Telegram-бот @nikah_istina_bot — **одна система с одной базой данных**. Анкета, отклик или сообщение, созданные в боте, сразу видны на сайте, и наоборот. Это не «синхронизация двух баз», а два интерфейса к одному серверу, поэтому расхождений быть не может.

Принципы продукта (из анализа рынка, `reports/Рынок никах платформ Россия и мир.md`):

1. **Без фото.** У обоих полов вместо фото безликий силуэт. ИИ-аватары — позже и только после письменного заключения учёных.
2. **Отклик → согласие → чат.** Написать можно только после того, как вторая сторона приняла отклик. Это защищает сестёр от спама.
3. **Вали.** Человек (в первую очередь сестра) может подключить вали, и тот получает копии всей переписки в Telegram. Собеседник видит значок «Вали подключён».
4. **Анкета за 2 минуты.** Обязательные поля — минимум, остальное заполняется по желанию.
5. **Только для никаха.** 18+, только свободные для брака (не женат / разведён / вдов), без объявлений о многожёнстве.
6. **Данные в России.** Сервер в РФ (152-ФЗ: религиозные убеждения — особая категория данных), отдельное согласие на обработку.

## 1. Архитектура

```
             ┌──────────── VPS (Россия), docker compose ────────────┐
 Браузер ──► │ Caddy (HTTPS) ──► web: FastAPI + Jinja2/HTMX          │
             │                     │  ▲ SSE (живой чат)              │
             │                     ▼  │                              │
             │                PostgreSQL 16  ◄── LISTEN/NOTIFY ──┐   │
             │                     ▲                             │   │
 Telegram ◄─►│ bot: aiogram 3 (polling) + воркер outbox ─────────┘   │
             └───────────────────────────────────────────────────────┘
```

- **web** и **bot** — один Python-пакет `app`, общие модели и сервисный слой `app/services`. Бизнес-логика (лимиты откликов, правила чата, вали) живёт только в сервисах, а сайт и бот её вызывают. Поэтому правила одинаковы в обоих каналах.
- **Синхронизация в реальном времени.** Любое событие (новое сообщение, отклик, принятие) сервис пишет в БД и в таблицу `outbox`, а затем вызывает `pg_notify('events', …)` в той же транзакции.
  - **bot** слушает канал, забирает недоставленные записи outbox и отправляет уведомления в Telegram: получателю и вали. Раз в 5 секунд он дополнительно опрашивает outbox — на случай, если уведомление потерялось.
  - **web** слушает тот же канал и пушит событие в открытые вкладки через SSE. После переподключения браузер дозапрашивает сообщения `after_id`, так что ничего не теряется.
- **Вход на сайт через Telegram** — тот же аккаунт, что и в боте (ключ — `telegram_id`):
  - **deep-link**: кнопка «Войти через Telegram» открывает `t.me/nikah_istina_bot?start=login_<token>`. Бот подтверждает вход, и вкладка сайта сама авторизуется (опрос раз в 2 секунды). Работает без настройки домена в BotFather.
  - **Telegram Login Widget** (после `/setdomain` в BotFather) — проверка подписи HMAC-SHA256.
  - **magic-link из бота**: кнопка «🌐 Открыть сайт» в боте выдаёт одноразовую ссылку, которая сразу авторизует.
- Стек: Python 3.12+, FastAPI, SQLAlchemy 2 (async) + asyncpg, Alembic, aiogram 3, Jinja2 + HTMX (файлы хранятся у нас, без CDN), PostgreSQL 16, Caddy, Docker Compose.

## 2. Структура сайта (страницы)

| URL | Страница | Доступ |
|---|---|---|
| `/` | Лендинг: суть, 3 шага («анкета → отклик → никах»), принципы (без фото, вали, модерация), счётчики анкет, FAQ, кнопка «Создать анкету за 2 минуты» | все |
| `/login` | Вход через Telegram (deep-link + виджет) | все |
| `/profile/new` | Мастер анкеты в 3 шага на одной странице, согласие на обработку данных | вошедшие без анкеты |
| `/catalog` | Анкеты противоположного пола: фильтры (возраст от–до, город, семейное положение, дети, образование), постраничный вывод | вошедшие с анкетой |
| `/u/{id}` | Анкета: кнопки «Откликнуться» (с коротким сообщением) и «Пожаловаться» | вошедшие с анкетой |
| `/interests` | Отклики: входящие (принять / отклонить) и исходящие (статус, отозвать) | вошедшие |
| `/chats`, `/chats/{id}` | Чаты: список с непрочитанными; переписка в реальном времени, «Завершить общение», «Пожаловаться», значок вали | участники |
| `/me` | Моя анкета: просмотр, редактирование, статус модерации, скрыть/показать, удалить аккаунт | вошедшие |
| `/settings` | Вали (ссылка-приглашение, статус, отключить), уведомления в Telegram | вошедшие |
| `/admin` | Модерация анкет, жалобы, пользователи (бан), статистика | админы |
| `/privacy`, `/consent`, `/terms`, `/rules` | Политика конфиденциальности, согласие на обработку данных, соглашение, правила сообщества | все |

Каталог и анкеты закрыты от поисковиков (`noindex`, `robots.txt`) и доступны только вошедшим с анкетой: это защита от сбора данных.

## 3. Анкета

**Обязательные поля (≈ 2 минуты):** пол · имя или псевдоним · год рождения (18+) · город · семейное положение (не был(а) в браке / в разводе / вдов(а)) · количество детей · образование · занятость · пожелания к супругу.

**Необязательные:** рост · вес · род занятий · национальность · мазхаб · намаз · когда готов(а) к никаху · готовность к переезду · о себе.

Справочники:

- образование: среднее, среднее специальное, неоконченное высшее, высшее, учёная степень, религиозное;
- занятость: работаю, свой бизнес, учусь, не работаю;
- мазхаб: ханафитский, шафиитский, маликитский, ханбалитский, не указан;
- намаз: соблюдаю всегда, почти всегда, иногда, учусь;
- никах: как можно скорее, в течение 6 месяцев, в течение года, пока не знаю;
- переезд: готов(а), не готов(а), обсуждаемо.

**Статусы анкеты:**

- `pending` — на модерации. Человек уже может смотреть чужие анкеты, но его анкету пока не видно.
- `active` — опубликована.
- `hidden` — скрыта самим пользователем.
- `rejected` — отклонена, с причиной.

Премодерация включается флагом `PREMODERATION` (по умолчанию включена). Новая анкета сразу приходит админу в Telegram с кнопками «Одобрить» / «Отклонить», так что модерировать можно с телефона.

## 4. Отклики, чат, вали

- **Отклик** — запрос интереса с необязательным сообщением до 500 символов.
  - На одну пару может быть только один активный отклик.
  - Лимит — `INTEREST_DAILY_LIMIT` (по умолчанию 10) новых откликов в сутки.
  - Статусы: `pending` → `accepted` / `declined` / `cancelled`.
- **Принятие отклика** создаёт **чат** между двумя людьми. Писать могут только участники.
  - Сообщения — текст до 2000 символов, источник `web` или `telegram`.
  - Любой участник может завершить общение (чат закрывается) или пожаловаться.
- **Сообщение, отправленное на сайте**, бот доставляет собеседнику в Telegram: «💬 Имя (#id): текст» и кнопка «Ответить».
  - **Ответ в боте** попадает в тот же чат и сразу появляется на сайте.
  - Активный чат в боте выбирается кнопкой «Ответить» или через меню «💬 Чаты». Выход — `/stop`.
- **Вали.**
  - В настройках подопечный получает ссылку `t.me/nikah_istina_bot?start=wali_<token>` и передаёт её вали. Вали жмёт «Старт» и подтверждает.
  - После этого вали получает в боте копии всех сообщений подопечного в обе стороны, с пометкой, чья это переписка.
  - Собеседник видит в чате и в анкете значок «👁 Вали подключён — переписка видна вали».
  - Подопечный может отключить вали в любой момент.
- **Антимошенничество.** Сообщения и анкеты со стоп-словами (перевод денег, карта, крипта, инвестиции и т. п.) помечаются для модератора, но не блокируются.

## 5. Бот @nikah_istina_bot

Меню: **📝 Анкета** · **🔍 Смотреть анкеты** · **💌 Отклики** · **💬 Чаты** · **⚙️ Настройки** · **🌐 Открыть сайт**.

- **Создание анкеты** — те же поля, что и на сайте: справочники кнопками, необязательные поля можно пропустить. В конце — согласие на обработку данных (со ссылкой на `/consent`) и подтверждение 18+.
- **Просмотр анкет** — по одной карточке с кнопками «💌 Откликнуться», «➡️ Дальше», «⚠️ Пожаловаться» и фильтром по возрасту и городу.
- **Входящий отклик** — карточка анкеты с кнопками «✅ Принять» / «❌ Отклонить».
- **Deep-links:** `login_<token>` (вход на сайт), `wali_<token>` (стать вали), `p_<id>` (открыть анкету).
- **Команды:** `/start`, `/help`, `/stop` (выйти из активного чата), `/delete` (удалить аккаунт и данные).
- **Админам** (`ADMIN_TELEGRAM_IDS`) приходят новые анкеты на модерацию и жалобы, с кнопками.

## 6. Модель данных

`users` (telegram_id, username, phone?, is_admin, is_banned, notify_telegram, consent_at, last_seen) ·
`profiles` (1:1 с users, все поля анкеты, status, moderation_note) ·
`interests` (from_user, to_user, message, status) ·
`conversations` (user_a, user_b, closed_at, closed_by) ·
`messages` (conversation, sender, text, origin, read_at, flagged) ·
`guardians` (ward_user, guardian_user, invite_token, status) ·
`login_tokens` (token, kind login/magic, user, confirmed_at, expires_at) ·
`reports` (reporter, target_user, message?, reason, status) ·
`outbox` (kind, payload, created_at, sent_at, attempts).

## 7. Перенос текущего бота

1. Получить код и **схему** базы текущего бота с сервера `oldvps`. Сами данные в репозиторий не кладутся: он публичный, а это персональные данные.
2. Написать `scripts/import_legacy.py`. Скрипт запускается **на сервере** и переносит пользователей и анкеты в новую базу по `telegram_id`.
3. Остановить старый процесс бота: один токен не может одновременно опрашиваться двумя процессами. Затем запустить `docker compose up -d` с **тем же** `TELEGRAM_TOKEN`. Для пользователей бот остаётся тем же @nikah_istina_bot.

## 8. Что входит в MVP и что потом

**MVP (сейчас):** всё, что описано выше, плюс страницы с юридическими текстами (шаблоны, требуют проверки юристом), Docker Compose, инструкция по развёртыванию.

**Следующие версии:**

- значок «семейное положение подтверждено» (по документу);
- скрытое реальное фото с раскрытием конкретному кандидату;
- безликие и стилизованные аватары (после заключения ДУМ);
- оплата открытия контакта для братьев, тариф «живая сваха»;
- дублирование уведомлений в VK и Max;
- вход по СМС для тех, у кого нет Telegram;
- региональные посадочные страницы для SEO.

**Юридические вопросы к юристу до запуска:**

- уведомление Роскомнадзора об обработке персональных данных;
- текст отдельного согласия;
- нужна ли регистрация в реестре ОРИ;
- достаточно ли входа через Telegram для требований 406-ФЗ об авторизации, или нужно подтверждение номера телефона.
