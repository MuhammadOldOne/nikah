# Переключение со старого бота на «Никах Истина»

Пошаговый план перехода с текущего бота @nikah_istina_bot (aiogram + SQLite `data.db`, systemd-сервис)
на новую систему «сайт + бот» с общей базой PostgreSQL. Бот остаётся тем же (тот же токен),
пользователи сохраняют номера анкет, отклики, чаты и переписку.

Сервер уже подготовлен по [DEPLOY.md](DEPLOY.md), разделы 1–9. Что делает перенос и как читать его
отчёт — [LEGACY_IMPORT.md](LEGACY_IMPORT.md).

| Заглушка | Что подставить |
|---|---|
| `<папка_старого_бота>` | папка старого бота: там его `.env` и `data.db` (или путь из `DB_PATH` в его `.env`) |
| `<имя_сервиса>` | имя systemd-сервиса старого бота (`systemctl list-units --type=service \| grep -i bot`) |
| `example.ru` | домен сайта |

Реальные пути, имя сервиса, адреса и данные людей не записывайте в репозиторий и чаты.

**Время простоя бота** — от остановки старого бота (шаг 3) до запуска нового (шаг 6): обычно
**3–5 минут** (копия базы и перенос занимают секунды, запуск бота — до минуты, остальное — проверки).
Выберите тихое время (например, утро буднего дня) и закладывайте окно 15–20 минут на случай отката.

## 0. Перед началом

- [ ] Сервер подготовлен ([DEPLOY.md](DEPLOY.md) 1–9): Docker, код в `/opt/nikah`, заполненный `.env`
      (тот же токен, админы, `WITNESS_CHAT_ID`, `TELEGRAM_PROXY`), выбран режим Caddy или nginx,
      DNS указывает на сервер, прокси Telegram проверен (раздел 6).
- [ ] Установлен `sqlite3` (`sqlite3 --version`).
- [ ] Известны `<папка_старого_бота>`, путь к `data.db` и `<имя_сервиса>`:
      `systemctl cat <имя_сервиса>` показывает `WorkingDirectory` и команду запуска.
- [ ] Есть тестовый аккаунт Telegram с анкетой в старом боте (для проверки в шаге 7) и доступ к
      группе свидетелей.
- [ ] Предупредите админов и свидетелей о времени переключения.

## 1. Поднять базу и сайт (без бота)

```bash
cd /opt/nikah
docker compose build
docker compose up -d db web caddy     # режим Caddy
docker compose up -d db web           # режим nginx (Caddy не называйте: он бы запустился)
docker compose ps                     # db и web — healthy, бота в списке нет
curl -fsS https://example.ru/healthz  # {"status":"ok"}
```

`web` при старте сам создаёт схему базы (`alembic upgrade head`). Сайт открывается, но войти на него
пока нельзя: вход подтверждается в новом боте, а он ещё не запущен. Так и должно быть: до переноса
в новой базе не должно появиться ни одной анкеты.

**Бот не запускать**: `docker compose up -d` без списка сервисов запустил бы и его.

## 2. Пробный перенос на копии (старый бот ещё работает)

Копия делается через `.backup` — это целостный снимок даже работающей базы:

```bash
install -d -m 700 /opt/legacy
sqlite3 "<папка_старого_бота>/data.db" ".backup /opt/legacy/data-test.db"
chown 10001:10001 /opt/legacy/data-test.db && chmod 400 /opt/legacy/data-test.db   # 10001 — пользователь контейнера
```

Пробный прогон: файл подключается к контейнеру **только для чтения**, всё проверяется и
**откатывается**, в новую базу ничего не записывается:

```bash
docker compose run --rm -v /opt/legacy/data-test.db:/legacy/data.db:ro web \
  python -m scripts.import_legacy --import /legacy/data.db
```

Отчёт содержит только количества (без имён, текстов и id), его можно переслать разработчику.
Сверьте колонку «в старой базе» с самой базой:

```bash
sqlite3 -readonly /opt/legacy/data-test.db "SELECT 'users', count(*) FROM users UNION ALL
  SELECT 'profiles', count(*) FROM profiles UNION ALL SELECT 'interests', count(*) FROM interests UNION ALL
  SELECT 'chats', count(*) FROM chats UNION ALL SELECT 'messages', count(*) FROM messages UNION ALL
  SELECT 'muted', count(*) FROM muted;"
```

Ожидаемо: «пропущено» — `0`, предупреждений нет или они понятны (что значит каждое и что делать —
[LEGACY_IMPORT.md](LEGACY_IMPORT.md), «Предупреждения»). Если что-то непонятно — остановитесь и
пришлите разработчику **только отчёт**. Старый бот всё это время работает, пользователи ничего не замечают.

## 3. Остановить и отключить старый бот

Telegram отдаёт обновления бота только одному процессу. Если старый и новый бот работают с одним
токеном одновременно, оба получают `Conflict`, а сообщения достаются то одному, то другому. Поэтому
старый бот нужно **остановить** и **отключить автозапуск** (иначе он поднимется после перезагрузки):

```bash
systemctl stop <имя_сервиса>
systemctl disable <имя_сервиса>
systemctl is-active <имя_сервиса>      # inactive
systemctl is-enabled <имя_сервиса>     # disabled
ps aux | grep -v grep | grep -F "<папка_старого_бота>"   # пусто: процесса нет
```

С этого момента бот молчит. Сообщения, которые люди пишут боту, Telegram хранит до 24 часов, и новый
бот получит их после запуска (шаг 6).

## 4. Финальная копия базы

Старый бот остановлен, база больше не меняется:

```bash
sqlite3 "<папка_старого_бота>/data.db" ".backup /opt/legacy/data.db"
sqlite3 -readonly /opt/legacy/data.db "PRAGMA integrity_check;"     # ok
chown 10001:10001 /opt/legacy/data.db && chmod 400 /opt/legacy/data.db
```

Сам `<папка_старого_бота>/data.db` больше ничем не изменяется и остаётся для отката.

## 5. Перенос с `--commit`

Ещё раз пробный прогон на финальной копии (секунды), затем запись. Отчёт сохраните (в нём только
количества):

```bash
docker compose run --rm -v /opt/legacy/data.db:/legacy/data.db:ro web \
  python -m scripts.import_legacy --import /legacy/data.db
docker compose run --rm -v /opt/legacy/data.db:/legacy/data.db:ro web \
  python -m scripts.import_legacy --import /legacy/data.db --commit | tee /root/nikah-import-report.txt
```

В конце отчёта: «Перенос записан в базу. Повторный перенос невозможен.» Повторный запуск с `--commit`
откажется работать — это защита от дублей.

## 6. Запустить новый бот

Тот же токен, что у старого бота, уже в `.env`:

```bash
docker compose up -d
docker compose ps
docker compose logs -f bot     # Ctrl+C, чтобы выйти
```

В логах должны быть `connected to Telegram as @nikah_istina_bot` и не должно быть `Conflict` и
`Unauthorized`. Новый бот запускается **без** сброса накопившихся обновлений: сообщения, написанные
за время простоя, будут обработаны сразу после запуска.

## 7. Проверка

- [ ] **Сводка админки** https://example.ru/admin, блок «Перенос из старого бота»: числа в колонке
      «Перенесено» совпадают с колонкой «перенесено» отчёта (`/root/nikah-import-report.txt`); «Сейчас в
      базе» сразу после переноса такие же и дальше растут по мере того, как люди пользуются ботом.
- [ ] **Тестовый аккаунт, `/start`**: привычное меню («Смотреть анкеты», «Моя анкета», «Мой чат», …);
      бот один раз просит согласие на обработку данных (152-ФЗ) — дайте его.
- [ ] **«Моя анкета»** показывает прежний номер «Анкета №N» и предлагает «Дополнить анкету».
- [ ] **«Мой чат»**: открытый чат на месте; история переписки видна на сайте (`/chats`) и в админке
      (https://example.ru/admin/chats).
- [ ] **Вход на сайт**: «Войти через Telegram» → подтверждение в боте → вкладка авторизовалась.
- [ ] **Свидетель**: тестовое сообщение в открытом тестовом чате → в группе свидетелей (или у админов
      в личке) появилась копия «Чат #… | №A → №B (Telegram)» с кнопками «⚠️ Пометить», «✍️ Написать в
      чат», «🚫 Закрыть чат».
- [ ] **Старые кнопки** в истории Telegram работают: например, «Принять» под старым откликом либо
      принимает его, либо отвечает, что отклик уже обработан.
- [ ] **Админ**: `/admin` в боте показывает очередь модерации.
- [ ] `docker compose logs --since 10m bot web` без ошибок.

Если всё в порядке, переход завершён. Копии `/opt/legacy/*.db` удалите через несколько дней
(`rm -rf /opt/legacy`), когда откат точно не понадобится. Папку старого бота с `data.db` храните
оговорённый срок и затем удалите: хранить персональные данные дольше необходимого нельзя.

## Что заметят пользователи

- **Бот тот же**: те же имя, меню и команды, номера анкет «Анкета №N» не меняются, открытые чаты и
  отклики на месте. Появились сайт, вали, отклики с сообщением и настройки.
- **Сообщения за время простоя не теряются**: Telegram хранит недоставленные обновления около 24 часов,
  и новый бот их не сбрасывает, а обрабатывает после запуска. Нажатия кнопок за время простоя тоже
  обрабатываются, но всплывающий ответ на них может не появиться (Telegram ждёт его недолго).
- **Незаконченная регистрация начинается заново**: старый бот держал её в памяти. На старые кнопки
  регистрации бот отвечает «Анкету заполняем заново: нажмите «Создать анкету»». То же для свидетеля:
  начатое «✍️ Написать в чат» нужно нажать заново.
- **Согласие на обработку данных** спрашивается один раз при первом действии (152-ФЗ, отдельное согласие).
- **Дополнить анкету**: перенесённые анкеты остаются в каталоге; бот и сайт предлагают за минуту
  указать семейное положение, детей, образование и занятость.

## Откат

Когда: новый бот не подключается к Telegram, массовые ошибки в логах, перенос оказался неверным.

```bash
cd /opt/nikah
docker compose stop bot                       # сначала новый бот: один токен — один процесс
systemctl enable --now <имя_сервиса>          # старый бот снова работает и запускается после перезагрузки
systemctl status <имя_сервиса> --no-pager     # active (running)
journalctl -u <имя_сервиса> -n 30 --no-pager  # ошибок нет
```

Сайт можно оставить работать или остановить: `docker compose stop web` (и `caddy` в режиме Caddy).

**Что теряется при откате.** Старая база (`<папка_старого_бота>/data.db`) не менялась, поэтому старый
бот продолжит с того места, где его остановили. Но в неё не попадёт ничего, что было сделано уже в
новой системе: новые анкеты и правки, отклики, чаты, сообщения, согласия, входы на сайт. Кроме того,
старый бот при запуске **сбрасывает** накопившиеся обновления: сообщения, отправленные боту между
`docker compose stop bot` и запуском старого сервиса, пропадут — делайте эти две команды подряд.

**Повторная попытка.** Перенос не повторяется в базу, где он уже был. Чтобы начать заново, сохраните
копию новой базы (`./scripts/backup.sh`) и пересоздайте её пустой, затем пройдите шаги 1–7 снова:

```bash
docker compose stop web bot
docker compose exec db psql -U nikah -d postgres -c "DROP DATABASE nikah WITH (FORCE);" -c "CREATE DATABASE nikah OWNER nikah;"
docker compose up -d web         # web создаст схему в пустой базе
```
